# 预览、续训与画质对照实验

## 创建视频世界

创建界面的视频入口默认勾选 **Preview first**。目标档位仍决定采样帧、分辨率与最终训练预算；预览只先训练 2,000 步，保持与后续精修相同的素材和设置，避免重新做相机求解或从头训练。

预览完成后，任务持久化为 `awaiting_review`，不会自动发布世界。页面展示原始观测 / 预览渲染对比，以及验证组指标：

- **Continue refining**：从预览检查点继续，只补足目标总步数。例如目标 20,000 步，预览已跑 2,000 步，后续只追加 18,000 步。
- **Use preview**：不再训练，保留现有检查点；完成最终测试后发布。
- **Discard**：取消当前工作流，不发布；已有本地检查点保留。

关闭弹窗、刷新或重启服务后，待审核状态保留。重新打开创建弹窗可以回到预览，无需再次上传。浏览器本地只记录任务 ID，后端 JSON 保存实际状态。取消勾选 **Preview first** 可以直接完成所选档位。

如果 GPU 重建已完成、但资产发布失败，页面保留结果并提供 **Retry publishing**；重试不会重新上传或训练视频。

旧客户端未提交 `preview_first` 时仍走原来的直接训练流程，避免旧页面误等一个它不认识的中间状态。Python API 新增：

```text
POST /api/reconstruction-jobs/<id>/refine
POST /api/reconstruction-jobs/<id>/accept
GET  /api/reconstruction-jobs/<id>/preview/0
```

`refine` / `accept` 只允许作用于待审核任务，重复提交返回冲突；缺少检查点时拒绝续训。预览图仅从该任务固定的评测目录读取。

## 固定素材与三组视角

新数据集生成显式的 `train_filenames`、`val_filenames`、`test_filenames`。视角按拍摄顺序交错划分，首尾保留训练；通常约 80% / 10% / 10%。不足 5 帧时无法保证合理三组，保留旧划分并不宣称具有独立测试组。

预览和参数选择只查看验证组；用户作出精修 / 使用预览决定后，才评估测试组。各组检查文件哈希，避免改名后的相同图片跨组。相机与 SfM 点云仍可能使用全部帧，因此是外观训练的保留视角验证，不能冒充完全独立的几何真值测试。

`dataset/dataset_manifest.json` 固定图片哈希、相机、划分和初始化点云；`training_recipe.json` 固定分辨率、随机种子和正则化设置。续训使用原数据集，不重新生成或重采样；检测到冻结内容变化会拒绝继续。旧任务保持原划分，不在已训练模型上偷偷换一组评测图片。

## Splatfacto 检查点兼容

本机 Nerfstudio 1.1.5 先构建优化器，再加载模型；Splatfacto 加载时会替换高斯 Parameter 对象，导致优化器仍指向旧对象。本次真实续训在增密时触发 CUDA 索引错误，最小 CPU 复现也证实了参数引用不一致。

`backend/tools/train_splatfacto.py` 是续训入口：在原检查点加载完成后重新绑定优化器到现有模型参数，保留已恢复的 Adam 动量、步数、学习率和调度器。所有组先验证尺寸再更改，避免状态不匹配时部分修改。它不修改第三方安装文件，配置类名也不改变，标准 `ns-export` / `ns-eval` 仍能读取 YAML。

另一个已确认的版本行为：`max_num_iterations` 表示本次追加的步数。因此 Windows 包装器会用目标总步数减去检查点已完成步数，再传给训练器；达到目标时不重新训练。

实际 GPU 验证：从第 2,000 步检查点追加 500 步，导出的检查点为 `step-000002499.ckpt`；随后执行“使用现有结果”路径，追加训练步数为 0，检查点文件与修改时间均未改变，仍完成最终测试评测。

## 运行对照实验

```powershell
python backend/tools/compare_reconstruction.py <scene_sfm.json> `
  --out <new-experiment-directory> --iterations 2000 --camera-scale 0.5 --seed 42
```

两组均从头训练，素材、相机、划分、初始化点云、种子、分辨率和训练预算相同，只切换 `use_scale_regularization`。工具核对数据指纹，保存每组日志、验证报告与对比图；按验证 LPIPS 排序并保存选择后，才查看选中候选的测试组。不会自动改动生产默认参数。

产物包括 `comparison.html`、`comparison.json`、`off/validation/`、`on/validation/`。细长高斯占比按最长 / 最短轴比大于 10 统计，只是形状代理指标，不等于拖影或导航质量。

## 本次试验与边界

会议室单场景，87 个训练视角、11 个验证视角、10 个测试视角；种子 42、图像缩放 0.5、每组从头训练 2,000 步：

| 尺度正则化 | 验证 PSNR ↑ | 验证 SSIM ↑ | 验证 LPIPS ↓ | 轴比大于 10 的高斯 |
| --- | ---: | ---: | ---: | ---: |
| 关 | 18.072 | 0.6432 | 0.51715 | 27.37% |
| 开 | 18.150 | 0.6462 | 0.51760 | 0.63% |

按预设的验证 LPIPS 排序选择“关”，其最终测试 PSNR 18.777、SSIM 0.6426、LPIPS 0.48868。开启正则化显著减少细长高斯，但外观指标变化很小且方向不完全一致；单场景、短训练预算不足以支持全局默认切换，当前保持关闭。

结果保存在 `.artifacts/staged-reconstruction-validation/ab-2000/`。原有 5k 基线的分辨率和划分不同，不与本次数字直接比较。

无 GPU 的浏览器流程回归为 `python scripts/verify_preview_flow.py --url http://127.0.0.1:3000`，已接入 CI。它覆盖关闭 / 刷新后的预览恢复、精修、使用预览、丢弃、直接训练，以及发布失败后的无重训重试。真实训练、评测和检查点续训另以本地 GPU 运行验证。
